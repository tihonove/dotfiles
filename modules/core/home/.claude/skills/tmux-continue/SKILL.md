---
name: tmux-continue
description: Передать подзадачу или ответвление текущей работы в новое tmux-окно с отдельной сессией claude — собрать выжимку контекста из текущего разговора, стартовать новое окно claude с этим промптом (обычно задача уходит в свой worktree по правилам проекта). Аргумент — краткое описание подзадачи (опционально, если из разговора и так ясно). Работает только внутри tmux — вне tmux сразу останавливается.
---

Ты передаёшь подзадачу в параллельную сессию claude в новом окне текущей tmux-сессии.
Смысл: в текущем разговоре выяснились детали, которые нужны другой (под)задаче, и её
хочется вести параллельно, не раздувая эту сессию.

## 0. Проверка tmux — обязательно первой

Запусти `tmux-host-env` (без аргументов). Он отвечает, в какой панели tmux сидит
человек: при обычном запуске это `$TMUX` самой сессии, а если сессия запущена из
`claude agents` (там `$TMUX` пуст — она живёт в pty демона), — tmux-сессия, где
человек последним печатал. Не проверяй `$TMUX` сам — в сессии агента он пуст, хотя tmux есть.

Если `tmux-host-env` вернул ненулевой код — мы не в tmux: сообщи об этом одной
фразой («/tmux-continue имеет смысл только внутри tmux») и **остановись**. Ничего не
выдумывай, никаких обходных путей (nohup, фоновые процессы, новые терминалы).

## 1. Сформулируй задачу для новой сессии

Источник — аргумент скилла и текущий разговор. Если аргумента нет и из разговора не
очевидно, какую именно подзадачу отпочковать, — спроси пользователя.

Составь handoff-промпт. Это самая важная часть: новая сессия не видит этот разговор,
поэтому передай всё, что здесь уже выяснено и сэкономит ей работу. Структура:

```
# Задача
<что нужно сделать, в терминах результата>

# Контекст из родительской сессии
<факты, добытые в текущем разговоре и относящиеся к делу: пути к файлам
(file:line), причины багов, результаты экспериментов, принятые решения,
тупики, в которые уже сходили — чтобы не ходить второй раз>

# Ограничения и договорённости
<что решили НЕ делать, границы задачи, особые пожелания пользователя>

Работай по правилам проекта (CLAUDE.md / AGENTS.md). Задачу веди в отдельном
worktree по конвенциям проекта.
```

Последний абзац включай по умолчанию; если пользователь явно сказал «без worktree»
или задача не привязана к репозиторию — опусти или замени по смыслу. Пиши промпт на
языке, на котором идёт текущий разговор.

## 2. Запусти окно

1. Запиши промпт в файл в scratchpad-каталоге (не пытайся протащить текст через
   кавычки в командной строке): например `<scratchpad>/handoff-<slug>.md`.
2. Придумай короткий kebab-case слаг подзадачи — он станет именем окна.
3. Стартовый каталог окна — корень основного репозитория (не текущий worktree,
   если ты в нём): новая сессия сама уйдёт в свой worktree по правилам проекта.
   Если пользователь просил конкретный каталог/worktree — используй его.
4. Создай окно:

   ```sh
   tmux-host-env tmux new-window -n "<slug>" -c "<каталог>" 'claude "$(cat <путь-к-файлу-промпта>)"'
   ```

   `tmux-host-env` впереди подставляет найденные `TMUX`/`TMUX_PANE`, и окно
   открывается в сессии человека, в том числе из-под `claude agents`. Не заменяй
   это на `eval "$(tmux-host-env)"` — такую форму режут песочницы.

   Команду в кавычках передавай **одинарными** кавычками, чтобы `$(cat …)`
   раскрылся уже внутри нового окна. Без `-d` — tmux сразу переключит пользователя
   в новое окно; это ожидаемое поведение (он сам решает, когда вернуться).

## 3. Отчитайся

Одной-двумя фразами: имя созданного окна, каталог, и в одну строку — что за задача
туда ушла. Файл промпта не удаляй (claude читает его в момент старта окна, но пусть
останется для отладки).

## Ошибки

- Нет бинаря `tmux`, `claude` или `tmux-host-env` в PATH — сообщи и остановись.
- `tmux new-window` вернул ошибку — покажи её пользователю как есть, не пытайся
  чинить обходами.
