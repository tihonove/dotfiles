# uncommit: коммиты → правки в рабочей копии

Пользователь ревьюит работу по **рабочей копии**, а не по коммитам, и вносит
исправления прямо в код. Агент при этом коммитит по ходу (это ок), а когда
пора смотреть — коммиты разворачиваются mixed-reset'ом: ветка откатывается на
базу, файлы остаются как есть, дифф виден в `git status`/IDE.

Всё делает скрипт рядом со скилом:

```
~/.claude/skills/uncommit/uncommit.sh [--all | --last [N]] [--here | --main] [--base <ref>] [-n] [<ветка>]
~/.claude/skills/uncommit/uncommit.sh --restack [<ref>]
```

Запускать из worktree ветки (cwd агента). Скрипт сам находит основной worktree,
базовую ветку (`origin/HEAD` → `origin/trunk` → `origin/main`) и сохраняет
прежний tip в `refs/uncommit/<ветка>`.

## Два выбора

| вопрос | варианты |
|---|---|
| **что разворачивать** | `--all` — всю задачу (до merge-base с базовой веткой); `--last [N]` — только последние N коммитов, например уточнение после замечания |
| **где смотреть** | `--here` — на месте, в worktree ветки; `--main` — перенести в основной worktree (ветка выписывается там, worktree агента остаётся detached на прежнем tip) |

Аргументы `/uncommit` — слова в любом порядке: `all`/`last [N]`, `main`/`here`,
`restack`, `dry-run`, имя ветки. Например `/uncommit last main`,
`/uncommit all`, `/uncommit restack`.

## Шаг 1: спросить, если не сказано

Параметры помнить не нужно. Всё, чего нет в аргументах, **спросить одним
`AskUserQuestion`** (оба вопроса в одном вызове, если не задано ничего), не
угадывать и не брать дефолты скрипта:

- **Что разворачивать?** — «Всю задачу» (все коммиты ветки до базы) /
  «Последний коммит» / «Последние N коммитов» (N уточнить через Other).
- **Где смотреть?** — «В основном worktree» (ветка переедет туда) /
  «Здесь, на месте».

Рекомендованный вариант ставить первым с пометкой «(Recommended)» по контексту:
если агент работает в отдельном worktree — «В основном worktree»; если
последний коммит был ответом на замечание пользователя — «Последний коммит»,
иначе «Всю задачу».

Перед вопросом полезно показать `-n` (dry-run): там список коммитов и что куда
поедет, по нему проще выбирать.

## После запуска

- Пересказать вывод: какие коммиты развёрнуты, в каком каталоге теперь лежит
  ветка, что в `git status`.
- После `--main` рабочий каталог агента отвязан (detached HEAD). **Не коммитить
  там.** Дальнейшая работа по ветке — в основном worktree, либо после того как
  пользователь вернёт её обратно.
- Не коммитить развёрнутое заново по своей инициативе: это состояние для ревью.

## Возврат: restack

Когда пользователь поправил код и хочет коммиты обратно:

```
uncommit.sh --restack            # из worktree, где лежит ветка
```

Ветка возвращается на сохранённый tip (или `origin/<ветка>`, если сохранённого
нет; можно указать ref явно), файлы не трогаются, и в рабочей копии остаются
**только правки ревью** — их коммитить отдельным коммитом поверх
(`git commit -a`), не amend. Сообщение коммита — по сути правок.

## Отказы скрипта

- «основной worktree грязный» / «в worktree ветки есть незакоммиченное» при
  `--main` — сказать пользователю, что там лежит; stash/commit решает он.
- «ветка не выписана ни в одном worktree» без `--main` — ветка без worktree
  разворачивается только в основной.
- «HEAD не предок …» на restack — ветка уехала после uncommit; не чинить
  автоматически, показать `git log` и спросить.
