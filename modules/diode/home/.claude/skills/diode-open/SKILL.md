# Открыть в diode

Скрипт `diode-here` режет текущее окно tmux: diode встаёт слева главной панелью
(66% ширины, лейаут main-vertical), эта сессия уезжает в колонку справа. Человек
закрывает diode — панель схлопывается, сессия снова во всё окно.

```sh
diode-here "$(git rev-parse --show-toplevel 2>/dev/null || pwd)"
```

Корень worktree, а не `pwd`: команды в сессии могут выполняться из подкаталога,
а открыть нужно репу целиком. Другой каталог просят явно — передать его.

Скрипт печатает id панели и выходит сразу — редактор живёт в своей панели, ждать
его не надо. Ответ человеку — одна строка: открыто, фокус в diode.

## Когда не сработает

- **Сессия запущена из `claude agents`** — `$TMUX` в ней пуст (она живёт в pty
  демона), но это не помеха: скрипт через `tmux-host-env` берёт tmux-сессию,
  где человек последним печатал, и ставит diode рядом с `claude agents` в ней
  (нет его там — рядом с активной панелью). Вызывать так же.
- **Не в tmux вовсе** — скрипт откажет, а не повиснет; так и сказать: открыть
  можно только внутри tmux-окна.
- **Повторный вызов на тот же каталог** — второй diode не откроется: скрипт
  найдёт уже открытую панель, снова сделает её главной и переведёт в неё фокус.
  Это норма, не ошибка.
- **Нет бинарника** — `modules/diode/update` из dotfiles ставит его в
  `~/.local/bin`.
